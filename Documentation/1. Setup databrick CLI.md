# Databricks CLI Installation on macOS

This guide installs the current Databricks CLI on a Mac, verifies it, and signs in to a Databricks workspace. The Homebrew CLI is a standalone command-line program; it does not need to be installed in a Python virtual environment.

## 1. Check for Homebrew

Open Terminal and run:

```bash
brew -v
```

If Terminal prints a Homebrew version, continue to Step 2. If it says `command not found`, install Homebrew from [brew.sh](https://brew.sh/), then open a new Terminal window and run `brew -v` again.

## 2. Install the Databricks CLI

Run these commands in Terminal:

```bash
brew tap databricks/tap
brew trust databricks/tap
brew install databricks
```

If `brew trust` is not recognized by your Homebrew version, skip that command and run the other two.

If you already installed the CLI with Homebrew and want to update it, run:

```bash
brew upgrade databricks
```

See Databricks’ [official CLI installation instructions](https://docs.databricks.com/gcp/en/dev-tools/cli/install).

## 3. Verify the CLI

Refresh the shell’s command lookup, then check which executable will run and its version:

```bash
rehash
which -a databricks
databricks --version
```

The Homebrew executable is commonly at `/opt/homebrew/bin/databricks` on Apple silicon Macs or `/usr/local/bin/databricks` on Intel Macs. The exact version will change as Databricks releases updates.

If more than one path appears, the first one is the command your shell will use. If it points to an old CLI inside a virtual environment, deactivate that environment and repeat the checks:

```bash
deactivate
rehash
which -a databricks
databricks --version
```

`deactivate` only turns off the virtual environment in the current Terminal session; it does not delete the environment.

## 4. Sign in to a Databricks workspace

Copy the workspace URL from your browser’s address bar. Use the base workspace URL, without a page path. Replace the example below with your URL:

```bash
databricks auth login --host "https://YOUR-WORKSPACE-URL" --profile free-edition
```

The CLI opens a browser so you can sign in. When finished, it saves a configuration profile named `free-edition` for this workspace. You can choose a different profile name if you prefer.

## 5. Verify the saved profile

```bash
databricks auth profiles
databricks auth describe --profile free-edition
```

The profile list should show your workspace and indicate whether the profile is valid. Do not share access tokens, passwords, or other credentials.

See Databricks’ [authentication documentation](https://docs.databricks.com/aws/en/dev-tools/cli/reference/auth-commands).

## Important: uploading files in Free Edition

A successful CLI installation and sign-in do not guarantee that every file destination is available. Many new workspaces, including Free Edition, do not support the legacy DBFS root. Therefore, a path such as `dbfs:/public/retail_db` may fail even when the CLI is installed and authenticated correctly.

For Free Edition, use a Unity Catalog volume or another supported storage location. See Databricks’ [DBFS guidance](https://docs.databricks.com/gcp/en/dbfs/).
