# Setup Dataset in DBFS Using Databrick CLI Commands

## Unity Catalog: Beginner Guide

This guide uploads the local `retail_db` folder into a Databricks Unity Catalog volume, then checks the uploaded files from a notebook.

## The idea in simple terms

Think of Unity Catalog as Databricks' organized, permission-controlled place for data:

- A **catalog** is the top-level container. In this example, it is `workspace`.
- A **schema** is a section inside a catalog. In this example, it is `default`.
- A **volume** is a managed place inside a schema for files such as CSV, JSON, and Parquet files. In this example, it is `retail_db`.

Together, `workspace.default.retail_db` identifies this volume. The files inside it are accessed by a path such as `/Volumes/workspace/default/retail_db/retail_db`.

We use Unity Catalog because it organizes data and controls who can access it. The volume is the destination for the files. The first `retail_db` in the path is the volume name; the second `retail_db` is a folder copied into the volume.

## 1. Create the volume in Databricks

1. Open your Databricks workspace.
2. Click **Catalog** in the left menu.
3. Find and open the **workspace** catalog.
4. Open the **default** schema under it.
5. Click **Create → Volume**.
6. Name the volume `retail_db` and create it.

You only need to create the volume once. The catalog and schema should already exist; if you don't see `workspace` or `default`, stop and check which names are available in Catalog before continuing.

## 2. Upload your local files from Terminal

Open Terminal and go to the `Databrick-Demo` project folder—the folder that contains `data`. For example, if the project is on your Desktop:

```bash
cd ~/Desktop/Udemy-DataEngineer/Databrick-Demo
```

Then copy the local `data/retail_db` folder into the Unity Catalog volume:

```bash
databricks fs cp data/retail_db dbfs:/Volumes/workspace/default/retail_db/retail_db --recursive --profile "firdaucazizah@gmail.com"
```

What the command parts mean:

- `databricks fs cp` tells the Databricks CLI to copy files.
- `data/retail_db` is the folder on your Mac.
- `dbfs:/Volumes/...` is the Databricks volume destination. The `dbfs:/` prefix is required by the Databricks CLI when it works with volume paths.
- `--recursive` includes files in subfolders.
- `--profile` selects the saved Databricks sign-in profile. Replace its name if yours is different; check with `databricks auth profiles`.

## 3. Check the files in a Databricks notebook

### Option 1

Using magic command:

```python
%fs ls dbfs:/Volumes/workspace/default/retail_db/retail_db
```

### Option 2

Open a notebook in your Databricks workspace. Choose a **Python** cell and run:

```python
display(dbutils.fs.ls("/Volumes/workspace/default/retail_db/retail_db"))
```

This code must run in a Databricks notebook, not in Mac Terminal.

- `dbutils` is Databricks' built-in set of notebook utilities.
- `dbutils.fs.ls(...)` lists files and folders at the path inside the parentheses.
- `display(...)` formats the results as a readable table in the notebook.

You should see the files and folders you uploaded.

### Option 3

Use command line to check:

```bash
databricks fs ls dbfs:/Volumes/workspace/default/retail_db/retail_db
```

## 4. Read a CSV file with Spark

After checking the listing, use the actual CSV path shown there. Replace `PATH_TO_CSV` with the file or folder you want to read:

```python
df = (spark.read
      .option("header", "true")
      .option("inferSchema", "true")
      .csv("/Volumes/workspace/default/retail_db/retail_db/PATH_TO_CSV"))

display(df.limit(10))
```

- `spark.read` tells Spark to load data.
- `header=true` says the CSV's first row contains column names.
- `inferSchema=true` asks Spark to guess column types, which is convenient for practice. For important work, defining the schema yourself is more reliable.
- `df.limit(10)` selects up to ten rows so you can preview the data.

## If something doesn't work

- Confirm the volume exists at **Catalog → workspace → default → retail_db**.
- Confirm Terminal is in the project folder that contains `data` before running the copy command.
- Confirm the profile name with `databricks auth profiles`.
- Use the exact catalog and schema names shown in your workspace. If they differ from `workspace` and `default`, update the command and notebook path to match.
- Run `display(dbutils.fs.ls(...))` in a Databricks notebook Python cell, not in Terminal.
