# Create a DataFrame from `schemas.json` Using PySpark

This guide reads the column names for `orders` from `schemas.json`, uses them to name a Spark DataFrame, and asks Spark to infer the column data types from the CSV values.

> **Important:** The examples below use the names from `schemas.json`, but `inferSchema=True` guesses the data types. This code does not apply data types that might also be stored in the JSON.

## 1. Check the CSV reader documentation

In a Python notebook cell, run:

```python
help(spark.read.csv)
```

This displays the parameters accepted by Spark's CSV reader. Among them are `inferSchema` and `header`.

## 2. Get the column names from `schemas.json`

If you already created the `columns` variable in an earlier notebook cell, you can skip this section. Otherwise, read and parse the JSON, then sort the `orders` columns by their position:

```python
import json

schemas_text = (
    spark.read
         .text(
             "/Volumes/workspace/default/retail_db/retail_db/schemas.json",
             wholetext=True
         )
         .first()
         .value
)

schema_data = json.loads(schemas_text)
columns_detail = schema_data["orders"]

columns = [
    item["column_name"]
    for item in sorted(
        columns_detail,
        key=lambda item: item["column_position"]
    )
]

columns
```

`columns` is now a Python list of names, in the same order as the CSV fields—for example:

```python
["order_id", "order_date", "order_customer_id", "order_status"]
```

The exact names come from your `schemas.json` file.

## 3. Read the CSV and give its columns names

The retail sample CSV files usually have no header row. In that case, Spark initially names the columns `_c0`, `_c1`, and so on. Use `toDF()` to replace those names with the names from `schemas.json`:

```python
orders_df = (
    spark.read
         .option("inferSchema", True)
         .csv("/Volumes/workspace/default/retail_db/retail_db/orders")
         .toDF("order_id", "order_date", "order_customer_id", "order_status")
)

orders_df.show()
```

`toDF()` renames the DataFrame columns in order. The number of names you supply must match the number of CSV columns.

## 4. Use the `columns` variable instead

Instead of typing each column name, unpack the `columns` list using `*`:

```python
orders_df = (
    spark.read
         .options("inferschema",True)
         .csv("/Volumes/workspace/default/retail_db/retail_db/orders")
         .toDF(*columns)
)

orders_df.show()
```

`*columns` passes each item in the list as a separate argument to `toDF()`. This is equivalent to writing:

```python
.toDF("order_id", "order_date", "order_customer_id", "order_status")
```

## 5. Check the result and inferred types

```python
orders_df.printSchema()
orders_df.show(10, truncate=False)
```

- `printSchema()` displays each column name and the data type Spark inferred.
- `show(10, truncate=False)` displays up to ten rows without shortening long values.

## If your CSV files have a header row

By default, Spark treats the first row as data. If the files have a header row, set `header=True` so Spark skips that row:

```python
orders_df = (
    spark.read
         .option("header", True)
         .option("inferSchema", True)
         .csv("/Volumes/workspace/default/retail_db/retail_db/orders")
         .toDF(*columns)
)
```

Use this only if the first line of every CSV file contains column names. If the files have no header, leave `header` unset (the default is `False`).

## What `inferSchema=True` does

Spark examines CSV values and guesses whether each column should be an integer, date, string, or another supported type. It is convenient for learning, but the result is an inference and may not match the intended type in every dataset. To use the exact types declared in metadata, build an explicit Spark schema from the type information in `schemas.json` instead.
